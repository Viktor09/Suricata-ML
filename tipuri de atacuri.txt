Layer 2 network attacks

i) ARP Spoofing/ARP Poisoning
- este un tip de atac MITM, deoarece ARP-ul nu are autentificare.

- protocolul ARP translateaza adresele IP in adrese MAC pentru ca dispozitivele din reteaua locala sa poata comunica. Se face broadcast catre toate dispozitivele de pe dispozitivul dorit si asa este primita adresa MAC a dispozitivului cu care vreau sa comunic (ARP REQUEST broadcast + ARP RESPONSE unicast).

- modul de functionare al atacului este in felul urmator: atacatorul trimite ARP Replay-uri false catre victima si/sau router, dupa care victima isi actualizeaza arp cache-ul cu MAC-ul atacatorului pt IP-ul routerului, router-ul isi actualizeaza arp cache-ul cu MAC-ul atacatorului pentru IP-ul victimei, tot traficul intre victima si gateway trece prin atacator

- simptome si indicatori intr-o retea compromisa: duplicari de adrese IP, mesaje ARP neobisnuit de des, intrari ARP se schimba brusc, gateway-ul devine inaccesibil. 

- din dataset am coloanele urmatoare: M=arp.hw.size, O=franme.ignored, Q=frame.marked, W=etg.ig, Y=frame.cap_len, Z=frame.encap_type, AA=frame.len, AE=arp.proto.size, AF=eth.lg, AJ=arp.opcode, AL=eth.type, AP=frame.time_delta, AX=label.


ii) DHCP Starvation
- DHCP Starvation consta in consumarea tuturor adreselor IP disponbiledin DHCP Poo, sunt trimise ii de DHC DISCOVER/REQUEST cu MAC random inventat,  

- DHCP procesul prin care unui device ii este atribuit automat o adresa IP, masca, gateway si dns. Acesta functioneaza in 4 pasi: DHCP Discover (descopera cine e server DHCP in retea si vrea o adresa IP), DHCP offer (server-ul ofera IP-ul cerut), DHCP Request (clientul spune ca vrea IP-ul respectiv), DHCP ACK (serveru confirma treaba asta).

- din dataset am coloanele urmatoare: ip.len, dhcp.option.type, udp.length, ip.dsfield.dscp, frame.ignored, ip.ttl, frame.marked, dhcp.option.dhcp dhcp.hw.len, eth.ig, ip.proto, frame.cap_len, frame.encap_type, frame.len, dhcp.option.end, udp.srcport, eth.lg, dhcp.hw.type, dhcp.type, eth.type, udp.dstport, frame.time_delta, ip.hdr_len, dhcp.option.length


iii) Rogue DHCP
- atacatorul porneste un server DHCP fals in retea si are ca scop sa dea gateway fals, DNS fals sisa faca MITM pe toata reteaua.

- semnaturi: 2 servere care raspund la acelasi discover; DHCP offer cu valori neobisnuite: gateway ciudat, lease time foarte mic/mare, DNS non-standard, subnet mask nepotrivit; rtt/delays neobisnuit de mici

- din dataset am coloanele urmatoare: A=ip.len, I=dhcp.option.type, J=udp.length, N=ip.dsfield.dscp, O=frame.ignored, P=ip.ttl, Q=frame.marked, T=dhcp.option.dhcp, U=dhcp.hw.len, W=eth.ig, X=ip.proto, Y=frame.cap_len, Z=frame.encap_type, AA=frame.len, AB=dhcp.option.end, AD=udp.srcport, AF=eth.lg, AG=dhcp.hw.type, AH=dhcp.type, AL=eth.type, AO=udp.dstport, AP=frame.time_delta, AS=ip.hdr_len, AV=dhcp.option.length, AX=label


iv) MAC Flooding

- atac asupra switch-urilor prin care atacatorul umple tabela CAM cu mii de adrese MAC false

- atacatorul trimite frame-uri etherenet cu MAC random, nu conteaza protocolul folosit

- cand switch-ul nu mai poate decide catre ce port tb sa trimita un frame unicast trece in FAIL-OPEN

- din dataset am coloanele urmatoare: A=ip.len, N=ip.dsfield.dscp, O=frame.ignored, P=ip.ttl, Q=frame.marked, W=eth.ig, X=ip.proto, Y=frame.cap_len, Z=frame.encap_type, AA=frame.len, AF=eth.lg, AL=eth.type, AP=frame.time_delta, AS=ip.hdr_len, AX=label
