ARP

- protocol de nivel 2 care mapeaza adresa IP a unui device cu cea MAC pentru a asigura conectivitatea cu alte deviceuri in reteaua locala
- gratuitous arp - pachet special de arp replay trimis fara sa fi fost cerut de nimeni. cazurile de mai jos evidentiaza cand apare.

--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
HSRP este un protocol de backup unde doua routere impart aceeasi adresa virtuala IP si MAC. Cand cel care functioneaza pica, cel secundar ii preia locul si anunta in retea sa trimita datele pe portul lui prin ARP Gratuitous.

Live Migration se refera cand o masina virtuala se muta de pe un server pe altul, o sa fie anuntat ca s-a mutat pe un alt port din switch.

Observatie! Indiferent daca HSRP sau Live Migration genereaza Grautious ARP, algoritmul pe care il implementez ce reduce rata Fals-Pozitivelor va lua in considerare frecventa pachetelor trimise intr-un interval de timp (10 pachete la 0.5-1s).
--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
Alte scenarii in care se mai pot genera fals pozitive sunt: aliasing-ul si port scanning-ul.

IP Aliasing inseamna ca un singur MAC poate avea mai multe IP-uri. Nu are sens sa il iau in considerare, are frecventa mica, plus ca are mereu perechea ARP Request + Replay.

Port Scanning implica trimiterea unor pachete catre mai multe adrese IP pentru a identifica dispozitivele active. In retelele locale cand folosesc nmap acest lucru functioneaza prin trimiterea rapida de cereri ARP Request broadcast.

Observatie! Chiar daca e un burst mare de pachete care se trimit, exista relatie de mai multe la cate end-device-uri sunt in retea request-replay.
--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------
- pasii de functionare al protocolului:
	a) ARP Request - un dispozitiv vrea sa afle adresa MAC asociata unui IP cunoscut, face broadcast catre toata reteaua locala, opcode = 1
	b) ARP Reply - se trimite unicast doar catre cel care a intrebat, opcode = 2
	c) Gratuitous ARP - ARP Replay trimis fara sa fi fost cerut de nimeni
	d) ARP Cache - memoria temporara a fiecarui dispozitiv, se salveaza perechile IP-MAC invatate pentru a nu face ARP Requesturi la fiecare pachet primit


- structura pachet ARP:
	*) hardware type
	*) protocol type
	*) hardware length
	*) protocol length
	*) op-code
	*) adresa MAC sursa
	*) adresa MAC destinatie
	*) adresa IP sursa (doar la request si reply)
	*) adresa IP destinatie (si la reply si request)
	*) lungimea frame-ului
	*) timestamp
